# Product planning

This folder contains the project planning structure. Fill it in as the team defines the product; no requirements, expected results, epics, stories, tasks, spikes, or IDs are assigned by these starter files.

| File | Purpose |
|:--|:--|
| [requirements.md](requirements.md) | Register functional and non-functional requirements |
| [expected-results.md](expected-results.md) | Register expected results and evidence of completion |
| [product-backlog.md](product-backlog.md) | Describe epics and index user stories with their GitHub Issue links |

Describe and maintain epics in the backlog file; epics do not have GitHub Issues. Keep user story descriptions and acceptance criteria in their GitHub Issues, while the backlog holds a short index. Tasks and spikes live **only in GitHub Issues**; do not copy them into Markdown tables or one-file-per-task documents. A spike is a time-boxed investigation with a question and a documented outcome. If work on a spike needs a branch, give its Issue a task ID so the branch follows the existing convention. No Issue templates are required.

Decide the ID format and task-number allocation before creating Issues, then never reuse an assigned ID. The GitHub `#number` is separate from the project ID.

This operational material is separate from `docs/report/`, which builds the single academic PDF. Refer to the relevant planning material from the report when needed.
